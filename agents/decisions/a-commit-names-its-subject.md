# A commit names its subject

**Decision record.** One decision, its alternatives, and why this one. Not a how-to — the law it
supports is in [document](../workshop/document.md).

**Context.** Info's commit crossed as a row index and its text (`DocumentActRequested` v1), and
the host wrote that row of whatever `Session::rows` held when the ask arrived. Measured through
the loaded pane with ordinary input at `b42fe35`: Return and a press on #2 in one poll wrote
`panel77` into #2 while the draft was on #1's `Name`. A load is a second boundary, because it
restores the file's mint: Return and `^o` over the document's own saved bytes wrote `panel77`
into the replacement's #1, and no row a picture showed had changed, so the pane had nothing to
abandon. A row number, a label or an object identity cannot say which document or which layout
a setter closes over once a mint can be restored or rewound.

**Decision.** The host names what its inspector rows address. `refocus`, which every rebuild of
the rows goes through, keeps the name while the rows are rebuilt for the same object in the same
layout and hands out one never used before otherwise; `open_on_first` drops it when a document
is opened, and `create` drops it when it mints an identity the document already held. The name
crosses in `v2::DocumentShown`, published beside v1 and said when the rows or the name moved. A
`DocumentCommitRequested` returns it with the row and the text, and the door refuses another
name before any row is read, moving no selection. v1's `commit` names no subject and is refused
in words; select, create and delete stay v1. A value moved under the same name is the same
property, and no merge policy is made.

**Alternatives considered.**
- *Tried: a row index judged against the current rows* — at `b42fe35` the one-poll press and the
  identical-bytes load each wrote into an object the draft was never typed for; the replacement is
  pinned by case `"an Info commit queued behind a press on another object, or on it and back, is
  refused: neither object is written and the pane says why"`.
- *Argued: the draft's object identity and label on the ask* — a load of identical bytes and a
  rewound mint keep both while the object behind them changes.
- *Argued: a new name at every rebuild* — a resize or a restored viewport would refuse work
  typed before it, for no change in what a row addresses.
- *Argued: requiring the shown value to be unchanged* — a merge policy nobody selected.
- *Argued: falling back to v1 when the new door is refused* — a second write, to a target nobody
  named.
- *Argued: an incarnation field in `WorkshopDoc`* — a durable format change for a session fact.

**Consequences.** A draft outlives a room, a refit, a restored viewport and a moved value; it
does not outlive another selection, a load or a re-minted identity. A pane speaking only v1 still
lists, selects, creates and deletes, and its commit is refused; an Info image that hears no v2
picture waits. A state swap to another document's bytes that re-mints nothing is not detected.
Names are counted per session, compared and never decoded.

**Laws supported.** [WL-DOC-21](../workshop/document.md).
