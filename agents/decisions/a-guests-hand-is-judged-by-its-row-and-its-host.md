# A guest's hand is judged by its row and its host

**Decision record.** One decision, its alternatives, and why this one. Not a how-to — the law it
supports is in [guests](../workshop/guests.md).

**Context.** A guest with `input` reached every control a key or a press reaches, and a guest's
Loom grant could not say less: a bus rule names a shape, and a key names none. So a guest could
make a recipe file of its own the catalog in force and build and load it, type into the Editor and
save the weaver's files, read the guests file's credentials in the Editor, run a shell through
Neovim's keys, and switch the weaver's editor from the Terminal. And one gesture counter served both
hands, so an agent's key made the weaver's pending approval stale. One Workshop could not both keep
a guest off the weaver's files and let an agent type and build on its own development Workshop.

**Decision.** The guests file names its version and, from version 2, whose host it is: a weaver's,
the default, or a development host. Admission records the row that admitted each session, and a
host seam answers it. An act that writes a file, builds or opens is an action class its owner asks
Workshop to approve for the gesture's hand, once, at the act's first beat, or at the beat that
learns its subject; a door past the dispatch asks about its sender. A guest builds only with the version-2 `build` power, and on a weaver's host
writes nothing, opens no guests file, types into no pane, and reaches neither the editor office,
whichever implementation holds it, nor the Terminal, nor the Hotkeys pane. Each hand keeps its own
gestures. A version-1 file still mounts, a weaver's host, and every row's losses are said beside
it at launch, on Attention and in Connections.

**Alternatives considered.**
- *The host fact as a launch flag of the development launcher* — argued against: the launcher has
  no guests file yet, and a file a person writes says it where the rows are.
- *No host fact: file writes under a power the weaver may grant on any host* — argued against:
  a power granted for an agent's own Workshop would be granted on the weaver's too.
- *A guest's Terminal line judged by the guest's own grant before the Terminal sends it* — argued
  against: the Terminal speaks as itself, so the line's author would be laundered through it.
- *A guest types and the weaver saves, each span's actor kept* — argued against: a submit of
  another actor's text would have to be refused per span, in every text-holding pane.
- *Neovim restricted to a command allow-list* — tried: Neovim 0.11.6 refuses `-Z` as an unknown
  option, and Vim's `-Z` never blocked `:w`; the office refusal stands whichever editor holds it.
- *Every key numbered, so a keymap edit's capture could be approved* — argued against: only an
  Escape asks a pane anything (WL-ARR-15); the Hotkeys pane, whose every act edits the keymap file,
  answers only the weaver's hand on a weaver's host instead.

**Consequences.** Shipped setups and the tower-defense story run their guest on a development host,
with `build` where they build. A guest on a weaver's host still reaches every
other control a key reaches, and the clipboard; loads are still admitted by trusting every
artifact; and an agent with a shell as the weaver's own user still writes the weaver's files.
