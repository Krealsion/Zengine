# Verification method — driving a live witness

Register `VM-WIT`, its first file: driving the real window or the real terminal — the control
target, the channel, the aim, the staging. Reading what the witness shows is in
[`witnesses-reading.md`](witnesses-reading.md). One method per heading; cite by ID. Router:
[`../verification.md`](../verification.md).

## VM-WIT-01 — Control target first

METHOD — Control target first: make one gesture whose effect you already know and assert it; unstick every modifier and send Escape twice at the start; assert the desk's starting picture before measuring.
BECAUSE — a modifier whose key-up an earlier run lost stayed down for the whole desktop, and the
next run's activation click arrived as a chord and photographed a desk in arrange mode.
SEEN — nowhere yet

## VM-WIT-02 — Launch isolated

METHOD — Launch with `--isolated`, so the per-user roots resolve to the designed absence and the witness reads and writes nothing of the maker's own state.
BECAUSE — a witness that reads the maker's own session, document or keymap measures that state
and can write it; the designed absence is what makes the run's picture the fixture's.
SEEN — `workshop/user_paths.hpp` `resolve_durable_path`.

## VM-WIT-03 — The channel lies silently

METHOD — The channel lies silently: build the input structs in compiled code, never by indexed assignment in a shell; prove the foreground with `GetForegroundWindow() == hwnd`; a screenshot photographs what is on top.
BECAUSE — an indexed assignment into an array of value types lands on a copy with no error, so
every event went out all-zero and was accepted and counted in full; a thread's own queue facts
name a buried window active, and only the foreground answers.
SEEN — nowhere yet

## VM-WIT-04 — Taking the foreground is one function that returns whether it worked

METHOD — Taking the foreground is one function that returns whether it worked: clear the lock timeout, attach input to both threads, restore, bring to top, set foreground, a topmost round trip, detach, return the check.
BECAUSE — setting the foreground alone is refused by the foreground lock when the caller does
not own the foreground, silently, and the window can still look right.
SEEN — nowhere yet

## VM-WIT-05 — A wide entry point needs the Unicode charset on the binding

METHOD — A wide-character entry point needs the Unicode charset declared on the binding, or a window title reads back as its first character.
BECAUSE — a builder marshalled as an ANSI buffer against a wide entry point reads the first
character and a NUL; four real titles were read as garbage from an unreachable desktop.
SEEN — nowhere yet

## VM-WIT-06 — Absolute mouse coordinates span the virtual desktop

METHOD — Absolute mouse coordinates span the VIRTUAL desktop: normalise against the virtual-screen origin and extent, and verify with the cursor position (one pixel of rounding is fine).
BECAUSE — absolute coordinates map onto the primary screen unless the virtual-desktop flag is
passed, so a click aimed at the middle of a window lands on another monitor.
SEEN — nowhere yet

## VM-WIT-07 — Aim lies

METHOD — Aim lies: a prose row is the face's line height and a prose column its advance (measured from three equal items); an arrow key needs its scancode form; a keystroke's box spans the notice row above it.
BECAUSE — a hover at the cell pitch kept changing the row above, an arrow in virtual-key form
did nothing, and an aim at the box's top clicked a row that consumes presses silently.
SEEN — nowhere yet

## VM-WIT-14 — A control experiment only controls what it can distinguish

METHOD — A control experiment only controls what it can distinguish: prefer a control whose SUCCESS path was seen working this session, and run the same binary from a harmless place before blaming the build.
BECAUSE — a broken harness and a dead input desktop produce identical readings, so a control
that agreed with the wrong diagnosis survived two phases; a crashing build booted fine elsewhere.
SEEN — nowhere yet

## VM-WIT-15 — Judge a live Windows witness on what it printed

METHOD — Judge a live Windows witness on what it PRINTED: under a Debug CRT a process dead on an unhandled exception is still alive with zero output, and a wait that returns false proves nothing.
BECAUSE — under the debug CRT an abort is a modal box, so with redirected handles a dead process
hangs where it died; the surviving run printed its whole banner, the dead one nothing.
SEEN — nowhere yet

## VM-WIT-16 — Author the session through the product's own writer

METHOD — When gestures are unavailable, author the session by calling `session_persist::to_text`, launch with an explicit `--session`, photograph, and report the gesture half as owed, never as driven.
BECAUSE — a hand-written session is a second drifting spelling of a format with a version, a
nested version and its own admission law; the photograph is half the claim and says so.
SEEN — `workshop/session_persist.hpp` `to_text`.

## VM-WIT-17 — The product's own laws read as failures when the driver forgets them

METHOD — The product's own laws read as failures when the driver forgets them: a draft opens on its current value (clear it before typing), and a run quits standing on the layout it means to reopen.
BECAUSE — a driver typed after opening a draft and wrote a negative into a row that refuses one,
then read the refusal as a broken commit; a run that quit on another layout reopened it.
SEEN — nowhere yet

## VM-WIT-18 — Pointer motion is a gesture with its own picture

METHOD — Pointer motion is a gesture with its own picture — settle the pointer on the target, then baseline, then gesture — and a press on a list row is an act, not a selection: select through a heading row.
BECAUSE — a frame diffed across pointer motion carries the hover, so a wheel's changed box spans
the whole desk; a press on a list row chose the row as the subject and starved both lists.
SEEN — nowhere yet

## VM-WIT-19 — The fix for a wrong aim is a smaller fixture

METHOD — The fix for a wrong aim is a smaller FIXTURE, not a cleverer search: plant a predecessor file that leaves one candidate, so a five-way search becomes two known presses.
BECAUSE — a planted predecessor file that names one unarrangeable pane turned a five-way search
into two known presses, every run; the search it replaced reported success over a pane that never
moved, because addressing a pane draws on the rows it watched.
SEEN — nowhere yet

## VM-WIT-21 — tmux is a TUI witness harness

METHOD — tmux is a TUI witness harness: a detached session at a stated size, `send-keys`, `capture-pane -p`; a mouse press is raw SGR bytes via `send-keys -H` at the terminal row; `resize-window` is a real resize.
BECAUSE — the detached session, the injected keys and the captured pane are the same three
questions a graphical witness asks; a resize through the multiplexer is a real terminal resize.
SEEN — nowhere yet

## VM-WIT-23 — A dead chord under a live legend never arrived

METHOD — A dead chord under a live legend means the gesture never ARRIVED: enumerate machine-wide remappers, then delivery, dispatch, paint; a posted key message bypasses hooks to prove the product's half.
BECAUSE — a machine-wide remapper consumed one chord and injected a different key; the legend is
a projection and stays truthful whether or not dispatch ever fires.
SEEN — nowhere yet

## VM-WIT-24 — The harnesses live with the phase records

METHOD — Working harnesses for both media are kept with the phase records, outside this repository, and are copied rather than rebuilt.
BECAUSE — the programs restate what these rows say, and a register restates the method, not the
program; rebuilding one costs the defects every row above was paid for.
SEEN — nowhere yet
