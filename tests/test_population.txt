# The Zengine test-population contract (C4, closing COLD-2 C-4).
#
# This file is the EXPECTATION half of "green means the population Zengine meant to run
# actually ran". It is read by tests/check_population.cmake, which the official lane
# tests/verify.cmake runs before it runs anything else.
#
# WHY IT IS A FILE AND NOT A DERIVATION. Everything else in a build knows what exists; only
# a written expectation knows what is MISSING. Delete `zengine_doctest_test(input ...)` from
# tests/CMakeLists.txt and CTest, the build tree, and every derived list agree instantly that
# there are nine entries and all nine passed -- which is exactly what COLD-2 measured
# (10/10 green after a whole TEST_CASE was deleted; exit 0 after a filter selected nothing).
# A list that is generated from the registrations cannot notice a registration that is gone.
# So this list is not generated from them, and removing one is a red.
#
# THE CONTRACT IS THREE CLAIMS, all fail-closed:
#
#   1. INVENTORY, exact.  For the gates active in this configuration, the set of entries
#      named here must equal, exactly, the set `ctest -N` reports. A missing entry fails; an
#      entry registered and never declared here fails too, and both are named. Adding or
#      renaming a CTest entry is therefore a deliberate act with a line in this file.
#
#   2. KIND.  Each entry's declared kind must match what the registration recorded about
#      itself, because the kind decides which population question is even meaningful. A
#      compile-negative test has no test cases to count and no floor is invented for it.
#
#   3. THE PER-KIND CONTRACT.  Below.
#
# THE KINDS, and what `detail` means for each:
#
#   doctest           A runtime doctest binary. `detail` is a per-suite case FLOOR: the
#                     binary must select at least that many test cases. Floors, never
#                     assertion totals: an assertion total is evidence to report, not a
#                     population, and it is not coverage. No contract file holds one --
#                     nothing would enforce it, so it would decay here unwatched, which is
#                     exactly what the figure that used to sit on this line did.
#
#   compile-negative  A compilation that MUST fail, judged on its diagnostic. `detail` is the
#                     exact PASS_REGULAR_EXPRESSION the registration must carry. Pinned here
#                     rather than merely observed, because "the compiler returned non-zero,
#                     therefore PASS" is the degradation these tests exist to avoid, and it
#                     is one deleted property away.
#
#   compile-positive  The control: the same fixture with the offence removed, which must
#                     BUILD. `detail` is empty, and the registration must carry no
#                     diagnostic pattern -- judging this one on output would let a fixture
#                     that never compiled satisfy it.
#
#   program           An ordinary program with no doctest population (the smoke test). The
#                     contract is that the entry exists, the binary exists, and CTest still
#                     runs the real command. No case count is invented for it.
#
#   script            A repository-owned CMake script run over the SOURCE TREE rather than
#                     over a build -- today, the documentation-link check. `detail` is empty:
#                     there is no binary to exist, no case to count and no diagnostic to
#                     judge, and inventing one of those would be a number that means nothing.
#                     Its registration being declared HERE is the point: the check reads the
#                     tree, so nothing in a build could notice it had stopped being run.
#
# FLOORS ARE MINIMUMS, and the numbers below are a MEASURED baseline (C4's, raised by W-0,
# W-1, W-2, W-3, W-4, W-5, W-6, BLD-0, PNL-0, PNL-1 and PNL-2 where those phases' cases
# should become permanent), so they carry ZERO downward slack --
# deleting a single test case from any suite crosses its floor -- while leaving healthy
# ADDITIONS free, which is the traffic this repository actually generates. Raise a floor when
# a phase's new cases should become permanent. Do not lower one to make a deletion green: a
# deliberate decrease in evidence is a reviewed edit to this file.
#
# `gate` says WHY a row may be legitimately inactive -- a conditional subpopulation stated
# explicitly instead of hidden behind a slack floor:
#
#   always  every supported test configuration has it; absence is always a defect.
#   sdl     rides the SDL-backed weaves (ZENGINE_SDL_SKIN=ON, the default; the Windows
#           stranger lane turns it off). Absent => declared absent, never "passed".
#
# An entry may carry MORE THAN ONE row, and a doctest floor is the SUM of the rows whose gate
# is active: `surface` is 35 cases everywhere plus 2 behind `#if defined(SURFACE_HAS_SDL)`
# (the SDL skin driven under the dummy video driver, and the same skin refused a video driver
# that does not exist), so its contract reads 37 where SDL is built and 35 where it is not,
# and neither number has any give in it. Since G-1 `input` carries the same split, for the
# same kind of case: a real SDL queue read by a real weave library, and both SDL weaves live
# at once.
#
# G-0's ten new cases are all in the ALWAYS row on purpose, and that placement is the
# claim: the SDL medium's whole label path is pure arithmetic in skin_sdl_plan.hpp, so the
# lane that builds no SDL at all -- the Windows stranger lane -- still proves that a
# SurfaceLabel reaches pixels, in which cell, in which ink, and clipped where.
#
# G-1 made the same placement decision twice more, and the split is worth reading as one
# rule: EVERYTHING PURE GOES IN `always`. The SDL translation (keys, modifiers, text,
# pointer coordinates, wheel, the close request) is pure code in input/translate_sdl.hpp
# and lands in input's always row; the pixel-to-cell projection is pure code in
# surface/pointing.hpp and lands in surface's. What rides the `sdl` gate is only what
# genuinely cannot exist without SDL -- one case per suite, each driving a real SDL against
# a real weave library.
#
# Keep this file plain ASCII: it is read with file(STRINGS), which treats a non-ASCII byte as
# a string terminator and would silently split the line around it. Two more characters the
# parser owns: `#` starts a comment (so a diagnostic pattern cannot contain one), and `;` is
# CMake's list separator and is refused outright rather than being eaten halfway through.
#
